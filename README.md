# مساعد ADB لشاشات BYD

تطبيق Android بواجهة عربية يحاول تفعيل ADB، ويفتح صفحات التطوير الموجودة في الشاشة ويعرض نتائج الفحص. **لا يوجد تأكيد بتوافق التفعيل مع إصدار BYD ‏23.1.83.2602236.1، ولم يُختبر التطبيق على السيارة الفعلية.**

## التنزيل والتثبيت

[تنزيل APK الجاهز](BYD-ADB-Helper-v1.0.apk) — افتح الملف ثم اختر Download raw file أو زر التنزيل في GitHub. يدعم Android 8 فأحدث، ومعماريات ARM وARM64 وx86 لعدم وجود مكتبات أصلية.

1. انقل APK إلى الشاشة وثبّته بالطريقة المتاحة فيها. إذا كان تثبيت التطبيقات نفسه مقفلاً، لن يمكن تشغيل هذا التطبيق قبل إتاحة التثبيت؛ وجود APK على USB لا يتجاوز قفل التثبيت.
2. أوقف السيارة على P وافتح «مساعد ADB».
3. اضغط «محاولة تفعيل ADB» وراجع النتيجة. لا يُعد انتهاء المحاولة دليل نجاح.
4. إذا رفض النظام، جرّب إعدادات المطوّر والتصحيح اللاسلكي أو قوائم BYD المتاحة.
5. عند استمرار المنع، افتح «مساعدة رمز الصيانة». قد يتطلب مسار QR اعتماد جهة صيانة؛ التطبيق لا يولّد الاعتماد.
6. استخدم «عرض التقرير وحفظه» لحفظ ملف TXT يساعد على تحديد ما يسمح به إصدار الشاشة.

## ما ينفذه التطبيق

- يقرأ إعدادات `adb_enabled` و`adb_wifi_enabled` و`development_settings_enabled`.
- بعد الضغط والتأكيد فقط، يحاول كتابة القيم الثلاث إلى `1`، ويسجل الرفض أو قيمة الإرجاع ثم يقرأ الحالة من جديد.
- يحاول `setprop persist.sys.adb.wiress.enable true` و`setprop sys.connect.adb.wiress 1`، بالهوية العادية للتطبيق؛ قد يمنعه Android أو SELinux.
- يفتح صفحات المطور وUSB والاتصال اللاسلكي عند توفرها.
- يفحص أنشطة تطبيقات النظام التابعة لـBYD وصفحات Android Settings التي تشير للتطوير؛ لا يعرض للتشغيل إلا الأنشطة المصدّرة والمفعّلة والتي يملك إذن فتحها. يستبعد الأسماء المرتبطة بالمسح أو ضبط المصنع أو التحديث أو المعايرة.
- يفحص الاستجابة على **127.0.0.1:5555 فقط**. الاستجابة ليست برهانًا بأن الخدمة ADB ولا أن الكمبيوتر مفوّض. غيابها لا ينفي منافذ التصحيح الأخرى أو اتصال USB.

## حدود الصلاحيات

Android لا يمنح `WRITE_SECURE_SETTINGS` لتطبيق عادي بمجرد تثبيته. لذلك فالتطبيق **أداة محاولة وتوجيه وتشخيص، وليس فتحًا مضمونًا لقفل BYD**. لا يستخدم root أو استغلال ثغرات أو شهادة BYD، ولا يغيّر برمجيات السيارة أو وحدات القيادة. لا ينفذ `adb tcpip` ولا يفتح منفذًا خارجيًا بذاته؛ إعدادات OEM هي التي تحدد طريقة تشغيل ADB.

إذا أتيح ADB مسبقًا واعتمدت الكمبيوتر، يمكن منح الإذن لهذا التطبيق مرة واحدة للمستخدم النشط:

```sh
adb shell am get-current-user
# استبدل USER_ID بالرقم الناتج:
adb shell pm grant --user USER_ID om.tariq.adbhelper android.permission.WRITE_SECURE_SETTINGS
```

هذا الأمر يحتاج ADB عاملًا أصلًا، فلا يحل قفل الوصول الأولي. التطبيق لا يعمل تلقائيًا عند تشغيل السيارة، ولا يحتفظ بخدمة خلفية. يمكن إيقاف التصحيح من إعدادات النظام بعد الاستخدام.

## الخصوصية

لا إعلانات أو حسابات أو اتصالات بخوادم. إذن INTERNET لفحص منفذ loopback المحلي فقط. إذن QUERY_ALL_PACKAGES لاكتشاف صفحات تطوير النظام. لا يطلب الموقع أو الهاتف أو التخزين العام، ولا يقرأ IMEI أو VIN أو ICCID أو جهات الاتصال. التقرير يُنشأ محليًا ويُحفظ فقط عند اختيار المستخدم. تتضمن بياناته موديل الشاشة وإصدار البناء وأسماء أنشطة التطوير والنتائج، ولا يرسلها التطبيق لأحد.

## البناء والتحقق

مطلوب JDK وAndroid SDK Platform 35 وBuild Tools 35.0.0. لا توجد تبعيات Maven أو Gradle. نفّذ:

```sh
export ANDROID_SDK_ROOT=/path/to/android-sdk
bash build.sh
```

يمكن تحديد `BUILD_TOOLS_DIR` و`ANDROID_JAR`؛ واستخدام Eclipse ECJ عبر `ECJ_JAR` إن لم يوجد javac. ينشئ البناء مفتاح توقيع محليًا داخل `.signing`؛ احتفظ به لإصدار تحديثات متوافقة. المفتاح الخاص غير مرفوع إلى المستودع.

يتحقق البناء من تسع قواعد تخص منع النتائج المضللة واختيار صفحات التطوير، ومن صحة توقيع APK. هذه فحوص بناء ومنطق وليست اختبار تثبيت أو تشغيل على BYD. `targetSdkVersion=28` للمساعدة على التوافق مع أنظمة السيارات؛ قد تختلف قيود التثبيت في الإصدارات المستقبلية.
